# Tenzor Helper Audit

> Library-wide audit of helper functions, classes, and utilities for necessity and professional standard. Discovery and reference-checking performed by parallel read-only agents; all dead/unused claims were adversarially verified against macro registration, pybind bindings, templates, CMake, tests, and examples. **No code was changed.**

## Executive Summary

The library-wide helper audit covered 19 units and surfaced 67 findings: 56 dead-code candidates (51 confirmed dead after adversarial verification, 5 refuted as actually-in-use), 6 redundant/duplicated helpers, 3 over-engineered abstractions, and 2 misplaced public symbols. The overall picture is healthy. Several large, high-traffic units (nn_layers, nn_core) showed zero issues, and most units reported only a handful of genuinely unused helpers rather than systemic rot. The dead code is concentrated in two recognizable categories: (1) "aspirational infrastructure" — helper utilities, dispatch macros, and RAII wrappers that were written speculatively for kernel/backend authors but never adopted (e.g. four stride utilities in core/stride_utils.hpp, five ONEAPI_DISPATCH_* macros, the entire cuda_fp16.hpp module, threading primitives atomic_add/atomic_cas/SpinLock/parallel_for/parallel_reduce), and (2) test-only or incomplete-feature scaffolding (gradient_utils validators used only in tests, jit GraphSegment/segments_ for unimplemented graph-break execution, sparse_helpers ActiveRowGrad). The most actionable cross-cutting redundancy is per-backend duplication of identical conversion utilities — dtype_from_string is copy-pasted across ROCm, CUDA, Vulkan, and the gRPC server, and to_nccl_reduce_op/to_nccl_datatype are duplicated between process_group.cpp and nccl_backend.cpp. Risk for nearly all removals is low: confirmed-dead symbols have no callers, and the duplications can be consolidated behind a single shared header without behavior change. Recommended approach is to delete confirmed dead symbols first (pure subtraction, no semantic risk), then consolidate the verified duplications, leaving the small judgment-call items (ToTensor identity transform, RoctxRange wrapper) for last.

## Recurring themes

- Aspirational/unused infrastructure: helper APIs written for future kernel or backend authors that were never adopted — stride utilities (core/stride_utils.hpp), five ONEAPI_DISPATCH_* macros, cuda_fp16.hpp, simd_dispatch fast_*/safe:: wrappers, threading primitives (atomic_add, atomic_cas, SpinLock, parallel_for, parallel_reduce). These inflate API surface and maintenance burden with zero callers.
- Per-backend copy-paste of identical conversion utilities instead of a shared header: dtype_from_string duplicated across ROCm/CUDA/Vulkan/grpc_server, and to_nccl_reduce_op / to_nccl_datatype duplicated between process_group.cpp and nccl_backend.cpp. A shared backend-utility header would eliminate drift (the CUDA dtype_from_string already diverged with extra integer types).
- Incomplete-feature scaffolding left in the tree: jit GraphSegment + CompiledFunction::segments_/has_segments_ for unimplemented segmented graph-break execution, sparse_helpers ActiveRowGrad/active_row_grad, StructuredPruningConfig designed but never wired into the API, and the nn_extras unused config struct.
- Test-only helpers masquerading as production API: gradient_utils validators (all_contiguous, same_dtype, same_device, extract_shapes, make_contiguous) and with_parent_grad_fn are exercised only by tests yet live in public headers.
- Semantic-duplicate / vestigial wrappers where a dominant idiom already exists: insertPreReadBarrier (3 uses) vs insertComputeOnlyBarrier (373 uses) do identical work; safeDispatch is unused; the ToTensor identity transform and RoctxRange RAII wrapper add indirection without functionality.
- Visibility leaks — pure implementation details exposed as public API: registry::get_pytorch_model_url and registry::initialize_default_registry in models/hub.hpp are only used internally and should be internal/private; clear_idle methods on the three CUDA handle pools are unused defensive API.

## Top priorities

1. **Delete the 51 confirmed-dead symbols, prioritizing whole-file/whole-group removals** — These are pure subtractions with no callers (adversarially verified), so behavior cannot change. Highest leverage targets: the entire cuda_fp16.hpp module, the five ONEAPI_DISPATCH_* macros, the four stride utilities plus unify_names, the five threading primitives, and the simd_dispatch fast_*/safe:: block (~200 lines). This single sweep removes the bulk of the maintenance surface at near-zero risk.
2. **Consolidate dtype_from_string into one shared backend-utility header** — Identical inline copies live in ROCm, CUDA, Vulkan kernel registries and grpc_server.cpp, and the CUDA copy has already drifted (extra Int16/UInt16/UInt32/UInt64 support). One canonical definition eliminates four-way duplication and the silent-divergence risk that this audit already observed.
3. **Consolidate the NCCL conversion helpers (to_nccl_reduce_op, to_nccl_datatype)** — Exact-duplicate logic exists as anonymous-namespace free functions in process_group.cpp (5 uses each) and as NCCLBackend private methods (19 uses each). Collapsing to a single location removes maintenance drift risk in the distributed comm path with no functional change.
4. **Remove incomplete-feature scaffolding: jit GraphSegment + CompiledFunction::segments_/has_segments_, sparse ActiveRowGrad, StructuredPruningConfig** — These represent never-finished features dangling in production headers. Removing them clarifies that segmented graph-break execution and structured pruning are not actually supported, preventing future readers from assuming working functionality exists.
5. **Fix the two visibility leaks in models/hub.hpp and remove unused handle-pool clear_idle methods** — registry::get_pytorch_model_url and registry::initialize_default_registry are pure internals exposed publicly (used only inside hub.cpp); moving them internal shrinks the public API contract. The three CuBLAS/CuSOLVER/CuSPARSE clear_idle methods are unused defensive API that can go. All low-risk, improves encapsulation.
6. **Address the small judgment-call cleanups last: ToTensor, RoctxRange, insertPreReadBarrier, gradient_utils test-only validators** — Lower value and slightly more nuance. ToTensor is a no-op identity transform kept for interface consistency; RoctxRange is wrapper-over-macro indirection; insertPreReadBarrier should fold into insertComputeOnlyBarrier (the 373-use dominant idiom); the gradient_utils validators are test-only and could either move to a test helper or be removed. Defer until the higher-value, zero-ambiguity work above lands.
